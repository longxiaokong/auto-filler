# 技术方案

## 技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 语言 | TypeScript | 类型安全；AI 编程工具生成代码的正确率更高 |
| 插件框架 | WXT | 约定式开发；自动生成 manifest.json；内置 HMR |
| UI | 原生 HTML + CSS + TS | Popup 和 Options 页逻辑相对简单，不引入 Vue/React |
| PDF 生成 | jsPDF（计划） | 纯前端拼装 PDF，无后端依赖 |
| LLM | OpenAI 兼容 API | 语义字段匹配；兼容任何 OpenAI 格式端点（OpenAI / DeepSeek / Ollama 等） |


## 核心流程

1. 用户在 Options 页录入个人信息（KV 字段 + 结构化 block）+ 管理材料文件 + 配置 API
2. 用户打开任意报名/申请页面，点击 Popup "扫描当前页面"
3. Content script 扫描页面所有 `<input>`、`<select>`、`<textarea>` 元素
4. 提取每个字段的语义线索：label 文本、placeholder、name 属性、aria-label
5. Background 调用 LLM API 做语义匹配 → 返回字段映射
6. 用户在 Popup 中确认 → content script 填充匹配字段或上传匹配材料

### 架构决策

#### LLM 接入：OpenAI 兼容 API

采用 OpenAI 兼容的 `/v1/chat/completions` 接口，用户自行配置：
- **API Base URL**（默认 `https://api.openai.com/v1`，可改为任何兼容端点）
- **API Key**
- **Model 名称**

匹配任务用小模型即可（gpt-4o-mini 级别），成本极低。

#### 数据存储

| 存储 | 内容 | 理由 |
|------|------|------|
| `chrome.storage.local` | API 配置 | 数据量小，API 简单 |
| IndexedDB `autoFillerDB` | 个人信息（KV + block）、材料文件 | 支持 Blob、索引查询、大容量 |

#### Popup / Background 职责分离

- **Background Service Worker**：执行扫描、LLM 匹配等耗时操作
- **Popup**：纯 UI 展示层，通过 `chrome.runtime.sendMessage` 与 Background 通信

#### 全插件内操作

所有功能在插件内完成：Popup 负责扫描/填充，Options 负责信息管理和设置。不依赖外部网页。

#### Content Script 注入

采用 WXT 声明式注入（`content_scripts` in manifest），匹配 `<all_urls>`。声明式比 `chrome.scripting` 动态注入更简单可靠。

## 存储结构

### chrome.storage.local — API 配置

```ts
interface ApiConfig {
  baseUrl: string;   // 默认 "https://api.openai.com/v1"
  apiKey: string;
  model: string;     // 默认 "gpt-4o-mini"
}
```

### IndexedDB: `autoFillerDB` v1

#### `textFields` — 键值文本字段

keyPath: `id` (autoIncrement)

```ts
interface TextField {
  id?: number;    // 自增主键
  key: string;    // 用户自定义 key，如 "姓名"
  value: string;  // 对应值
}
```

> TODO: P1 阶段升级为 KV 字段 + 结构化 block，支持项目经历、竞赛奖项等复杂数据类型。

#### `fileRecords` — 文件记录

keyPath: `id` (autoIncrement)
索引: `fileType`, `createdAt`

```ts
interface FileRecord {
  id?: number;              // 自增主键
  filename: string;         // 原始文件名
  fileType: string;         // 文件类型
  fileBody: Blob;           // 文件体
  fileSize: number;         // 文件大小 (bytes)
  fileDescription: string;  // 文件描述（用作材料名称）
  createdAt: number;        // 创建时间戳
}
```

## 关键 Chrome API

- `chrome.storage.local` — 持久化存储 API 配置
- `chrome.tabs` — 与当前标签页通信
- `chrome.runtime.sendMessage` — Popup / Background / Content Script 间消息传递
